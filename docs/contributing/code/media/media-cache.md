# 缓存 `Media`

用户可管理的视频下载见 [下载管理](media-downloads.md)。本文中的“缓存”指底层媒体存储机制。

Ani 目前支持缓存许多类型。主要可以分为三类：

- BT（磁力链接，种子文件）；
- HTTP 协议的视频文件（如 MP4）；
- HLS 流式传输资源（如 M3U8）。

BT 资源由 BT 引擎处理（Anitorrent），HTTP 和 HLS 资源由下载器 `HttpDownloader` 处理。

## BT 缓存的持久化

`TorrentMediaCacheEngine` 用两张表记录 BT 缓存：`torrent_cache` 以 `mediaId` 为主键保存种子数据与下载目录，
一个合集只有一行；`torrent_cache_episode` 以 `(mediaId, episodeId)` 为主键保存每集的完成状态、
种子内的文件路径与流量统计。同一合集的多集共用一行 `torrent_cache` 与一个下载会话，各自有一行 `torrent_cache_episode`；
删除某集只删除它的剧集行，合集没有剩余剧集时才删除种子行与文件。
`torrent_cache` 上的完成状态与文件路径列只用于恢复没有剧集行的旧记录（数据库版本 24 之前创建的缓存）：
恢复时按记录的剧集判断旧行的文件是否属于该集，是则沿用，否则重新从种子中选择文件，并补建剧集行。

## 缓存位置

缓存可以放在内部存储或外接盘上（`domain/media/cache/location/`）。`MediaCacheLocations` 列出此刻接着的位置
（`MediaCacheLocation`：内部存储的 `id` 为 `null`，外接盘为系统给这个卷的 UUID），并给出新缓存的位置
（`MediaCacheSettings.defaultLocation` 选的盘接着且能用时是它，否则是内部存储）。安卓实现 `AndroidMediaCacheLocations`
只用各盘上本应用的私有目录（`getExternalFilesDirs`），不用申请权限，原生库能直接按路径读写；卸载应用时系统会一起删掉。
FAT32（单个文件最大 4 GB）与只读的盘不能放新缓存。没有平台实现时只有内部存储（`InternalOnlyMediaCacheLocations`）。

- 各位置根目录下的布局相同（`anitorrent/pieces/<种子>`、`web-m3u/…`）。每条缓存只记它在哪个位置：BT 记在
  `torrent_cache.location`，网页缓存记在 `http_cache_download_state.location`（数据库版本 30 起；为空 = 内部存储，旧缓存都是）。
  换默认位置不影响已有的缓存。
- 一个种子只放一个位置：同一种子的其他剧集、别的数据源缓存的同一种子，都跟着已有的种子行。内部存储上的种子目录由引擎决定，
  别的位置上的经 `TorrentDownloader.startDownloadAt` 指定。网盘引擎（PikPak）的文件只放内部存储。
- 盘没接上时，恢复记录得到 `UnavailableMediaCache` 占位：不能播，暂停 / 继续不做什么，选源时不出现；删除只删记录，
  文件等下次带着这个盘启动时由清扫回收。绝不能把「盘不在」当成「文件丢了」去删记录或重新下载。
- 盘插拔时 `MediaCacheLocationRefresher` 让各存储重新恢复：拔掉的换成占位（网页缓存还在跑的任务先暂停），插回来的换回真的缓存。
  下完的缓存（`LocalFileMediaCache`）平时恢复一次就不再管，外接盘上的这时先用 `forgetRestoredLocalFiles` 让存储重新恢复它们。
  网页缓存下载出错时如果它所在的盘已经不在，记成暂停而不是失败，插回来后接着下。
- 启动清扫外接盘上的种子目录时，归属按数据库里的全部种子记录算（不只这次恢复出来的），恢复时盘还没接上的记录的目录不会被删。
- `DownloadSpaceGuard` 按位置分别检查剩余空间，只暂停快满的那个盘上的下载。
- 设置入口见下面「缓存放在哪」。控制台「缓存位置」卡片（`RemoteCacheLocationSetting`）只改盘，第二个按钮把还在别处的搬过去。

### 把已有缓存搬到别的位置

`MediaCacheMover` 把不在目标上的缓存一份一份搬过去（目标是 `MediaCacheMoveTarget`：位置，加上片库里的视频放公开片库还是应用目录里的片库）。
一份（`MediaCacheMoveUnit`）是 BT 的一个种子目录（合集的各集、别的数据源缓存的同一种子一起）、在线源的一个任务的文件，或片库里的一个视频。
各引擎的搬法实现 `MediaCacheEngineMover`（`TorrentCacheMover`、`HttpCacheMover`、`LibraryCacheMover`），只管文件与记录：

1. 在 `MediaCacheLocations.moving` 登记，存储重新恢复：引擎认出正在搬，给「正在移动」占位（`UnavailableMediaCache.moving`），
   下载会话 / 任务随之停下；
2. 复制到目标处的临时名字（`.izuko-moving`），边写边落盘，逐个核对大小，改成正式名字，再改记录（记录在搬的期间被删了就放弃）；
3. 取消登记，存储再恢复一遍，按新位置接着用；最后删原处。

第 2 步（复制到改完记录）持着 `MediaCacheLocations.moveLock`，启动清扫拿到这把锁之后才按记录认归属：
否则清扫会把正在复制的临时目录、改好名还没改记录的新目录当成没人用删掉，后者删掉之后记录照样改过去、原处照删，两份都没了。
出错或取消时这一份留在原处照常用，目标处复制了的清掉；留下的临时名字由启动清扫收掉。在播的番（同一部的任何一集，包括 TV 上退出播放页后在后台保留着的会话）跳过，
跳过的记下来（`MediaCacheMover.waiting`，存在应用私有目录的 `cache-move-waiting.json`），那部番不再播之后、或重开应用时接着搬
（`MediaStorageSetup.start` 按播放状态的变化与启动时的第一个值调 `MediaCacheMover.resumeSkipped`；这期间设置改了、用户取消了、整批停下了就不搬），
进度从已经搬好的接上；
目标盘剩余空间不够时整批停下。没下完的 BT 种子不带续传数据过去，到新位置后按哈希重新校验，复制时 BT 服务还在落的数据不会因此出错。
片库里的视频连说明文件与字幕一起搬，目标处同名的已经有别的文件时加 ` (2)`；原处的视频改记录后随即改成以 `.` 开头的名字，
搬完重新恢复时扫描只认新的那份；删掉原处之后，条目文件夹空了随即删掉（`MediaCacheEngineMover.afterSourcesDeleted`）。

## 片库

片库（`domain/media/cache/library/`）是盘上一个按约定命名的文件夹，里面每个视频当成一条下完的缓存。
每块盘上可以有两个（`LibraryPlace`）：
- **公开片库**：盘根目录下的 `Izuko/`，卸载、清除数据都不删，在电脑上也能直接看；要「所有文件访问」（`MANAGE_EXTERNAL_STORAGE`），
  位置与权限由平台给（`MediaLibraryAccess`，安卓 `AndroidMediaLibraryAccess`，安卓 11 起；按权限此刻的实际状态判断，用 adb 给的也算）。
  安卓 10 及以下没有片库：设置的「缓存放在哪」只说哪块盘、引导里没有「方式」那一步，Web 控制台不列片库那一项
  （这些系统上外接盘根目录写不进去，只放内部存储意义不大）。
  只在打开片库（`MediaCacheSettings.libraryEnabled`）时扫描；关掉之后索引里有的（还没移回应用目录的）照常列出、能播。
- **应用目录里的片库**：那块盘的缓存目录下 `izuko-library/`，不要权限，卸载时一起删。关掉片库时公开片库里的可以移回这里，总是列出。

下载照旧在应用目录里进行，下完的缓存再「发布」进片库（见下）。

- 命名（`MediaLibraryLayout`）：`<番名> [bgm-<条目 ID>]/<番名> - <集序> [bgmep-<剧集 ID>].<扩展名>`，旁边是说明文件
  `<视频文件名>.izuko.json`（原资源与剧集信息，即一条 `MediaCacheSave`）与外挂字幕 `<视频名>.<标签>.ass`。
  名字里带着编号，说明文件丢了也能按名字认回条目与剧集。同一集有几份时后来的加 ` (2)`。以 `.` 开头的文件不算。
- 片库文件夹才是准的。`LibraryMediaCacheStorage` 每次恢复（启动、插拔盘、开关或权限变了）先扫一遍此刻列出的片库，
  按扫到的更新本机索引（`MediaLibraryIndex`，应用私有目录，能随时重建）与缓存元数据，再照常恢复成 `LocalFileMediaCache`。
  所以在电脑上删掉、拷进来的视频，下次扫描就跟着变；卸载重装后扫一遍就认回来。片库的记录与下载的缓存在同一份元数据里
  （引擎键 `library`），开播的快速通道（`EpisodeCacheRecords`）照常认得。
- 有说明文件且编号对得上时用它记的原资源：`cacheId` 与发布前相同，播放线索、选源记忆不受影响。没有说明文件的视频
  （用户自己放进来的）按名字拼一份，原资源当成片库里的本地文件。
- 盘没接上或权限被关掉时，那些记录给 `UnavailableMediaCache` 占位，不删记录，同盘没接上的缓存；权限被关掉时占位带 `accessLost`，
  缓存页说「所有文件访问」被关掉了而不是盘没接上（关掉权限时系统会杀掉应用，下次启动就是这样；重新给权限后十秒内恢复）。
  关掉片库时选了留在文件夹里，公开片库里的从索引里去掉（`forgetPublic`），不再列出；文件不动，以后打开片库扫描时认回。
- 片库不下载（`supports` 为 `false`），启动清扫不碰片库。删除就是删文件，连说明文件与字幕，条目文件夹空了也删。

### 发布

`MediaLibraryPublisher` 在缓存下完、播放停下、搬缓存结束、片库开关或权限变了、插拔盘时（稍等几秒）过一遍各存储，
把下完的缓存复制进「缓存位置」那块盘（新缓存下到哪，`MediaCacheLocations.locationForNewCache`）的公开片库，别的盘上下完的跨盘复制；
片库认下（`LibraryMediaCacheStorage.adopt`）之后用原存储的 `delete` 删原缓存（只删缓存，不删弹幕）。
不看是哪种下载：BT 与在线源下完都是一个本地文件（`getCachedMedia` 给 `LocalFile`），在线源本地存的外挂字幕一并复制到视频旁边。

1. 视频复制到以 `.` 开头的临时名字（扫描不认），写好说明文件与字幕，最后改成正式名字。改名之前出错，这一份留在原处照常用，
   写了的都清掉；改名之后说明文件已经在了，扫描按它认回原资源，不会再发布一份。上次没复制完的临时文件下一遍开头清掉。
2. 片库认下之后、删原缓存之前，同一集两边各有一条，`MediaDownloadManager` 按 `cacheId` 去重，排在前面的下载存储那条先列，
   所以片库存储登记在存储列表最后。删原缓存失败时下一遍发现片库里已经有这一集这个资源，只删原缓存。
3. 跳过：在播的番（同一部的任何一集）、没有条目或剧集 ID 的、扩展名认不出的；目标盘写不了或剩余空间不够时这一遍停下；
   正在搬缓存时整遍不做。BT 缓存发布之后不再做种。

## 缓存放在哪

哪块盘（`MediaCacheSettings.defaultLocation`）与放不放进片库（`libraryEnabled`）一处说了算：`MediaStorageSetup`。
片库永远在那块盘上，只有一个。换盘、开关片库、把已有的搬过去由同一份计划（`plan`）算出要搬什么，`apply` 一次做完：

- 下载的缓存搬到那块盘的缓存目录。放进片库时，全部下完、能发布的下载不在这里搬，交给发布直接复制进那块盘的片库（只复制一次）；
- 片库里的视频搬到那块盘的片库：放进片库时是公开片库；不放时移回那块盘应用目录里的片库（没移回之前照常列出），或留在公开片库的文件夹里（不再列出，以后打开片库认回）；
- 打开片库时一并关掉「标记看过后删除缓存」：下完的缓存都在片库里，它删的就是片库里的视频；片库开着时再打开它先问一句。

`leftovers` 是按现在的设置还在别处的（选了只放新的、搬的时候那块盘没接上、关掉片库时没移回的；留在文件夹里的不在索引里，发布自己会做的也不算）。

设置入口：电视设置「存储」里一行「缓存放在哪」（`TvSettingsEntriesCacheLocation`），按下去进全屏引导（`StorageGuideDialog`，
步骤逻辑 `StorageGuideState`）：放在哪块盘 → 片库还是应用目录 →（选了片库又没权限时）去授权 → 已有的缓存怎么办 → 确认。
各步先选好现在的设置，按「完成」才生效，中途退出什么都不改。授权那一步打开系统页面（依次试只管这个应用的、所有应用的列表、应用信息页，
都没有时给 adb 命令），回来后看到权限给下来就自动往下走。下面两行有事时才出现：「移动已有缓存」（有 `leftovers`、又没在搬也没在等停播）、
「片库暂时不可用 · 重新授权」（片库开着而权限被关掉）。控制台的「片库」卡片开关后照引导的默认做法搬（`RemoteSettingSpec.onSaved`）。

搬的进度只在动作面板顶上的后台任务那一格（`TvBackgroundTasks`），设置页不重复：在电视上按「完成」或确认「移动已有缓存」后，
等那一格有了这件事再替用户弹一次面板（`showMoveInActionPanel` → `TvActionPanelRequests`，焦点落在任务上），从控制台开始的不弹。
搬家一开始就在那一格里：列要搬哪些要等各存储恢复完、盘扫完（盘慢或正忙时几秒），这期间进度条不定式地走、不写数。
正在搬时那一条右端是 ✕（停止）；在等停播时进度停在已经搬好的地方，右端是「继续」（关掉后台保留着的播放器，停播就接着搬）与 ✕（取消，剩下的留在原处）。
