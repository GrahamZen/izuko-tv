# 通知

本文定应用内通知的行为与接口：哪些事进通知、什么时候弹、怎么接一种新的事。

## 1. 一句话

**后台发生的、用户要知道或要处理的事汇成一个列表。每条一个标题与一行摘要，按确定去处理它的那一页或弹窗。** 每次进应用有没看过的就弹一次，平时在头像上亮红点。手机控制台上有同一份列表；控制台开着时新通知当场在手机上提示，播放时也能在手机上处理。

## 2. 目标与不做的

### 目标

| 编号 | 目标 |
|---|---|
| G1 | 用户不用记各种事去哪里看：反馈的回复、待处理的收藏、发版后的通知、订阅要处理的事都在一处 |
| G2 | 电视上不用手动找：进应用时有没看过的通知就自动弹出来 |
| G3 | 每次进应用最多被打断一次 |
| G4 | 接一种新的事只要三步：写一个种类、登记一行、在事件发生处发出去（或接上状态） |
| G5 | 在哪里处理掉的（电视上、手机控制台），通知都跟着消失 |
| G6 | 电视在播放时不被打断，用户也能当场在手机上看到并处理新通知 |

### 不做的

| 不做 | 原因 |
|---|---|
| 系统通知（通知栏） | 电视上的系统通知不好用，多数用户看不到。手机上也发不了：控制台是局域网里的 http 页面，浏览器不让这种页面发系统通知 |
| 服务器推送 | 应用不依赖自己的服务器；通知都由这台电视上的事产生 |
| 列表一行里放按钮 | 一行只写标题与摘要；说明与操作在右栏，聚焦那一条时才出现 |
| 进度类的消息（每集下好了、同步完成） | 发生得多、不用处理；订阅页的点、各页面的状态已经说了 |
| 图片、详情页 | 一条的说明在右栏几句话说完；要细看的去去处看 |

## 3. 概念

| 词 | 意思 |
|---|---|
| 通知 | 一条：种类、键、参数、时间。显示的标题、摘要与去处由种类决定 |
| 种类 | 一类事，如「反馈有新回复」。每个种类定文案与去处 |
| 类别 | 列表行左边的图标、右栏标题上面的签：公告、更新、反馈、收藏（订阅分支还有订阅、下载）。按处理它要去哪一处分，图标取侧边栏、设置里同一处已有的 |
| 标题 | 怎么了，短到一行放得下（如「反馈有新回复」「新版本 1.0.9」）。列表、气泡、手机上的横幅都写它 |
| 摘要 | 列表里标题下面那一行：是哪一个（作品、反馈），或说明的开头（如公告冒号后面那半句）。可以没有 |
| 键 | 这一件事的标识。同一个键只有一条 |
| 跟着状态的 | 一个状态在它就在、状态没了它自己消失的通知（如有本地收藏待处理、这一版有发版后的通知）。不存，每次从状态算 |
| 消息 | 发生过的一件事（如续集公布）：存下来，看过算读，30 天后或超过 100 条时最早的清掉 |
| 说明 | 聚焦一条时右栏写的：怎么了、为什么、能做什么，几句完整的书面句子；可以分几段，一段可以带小标题（如新版本里一项改动的名字）。种类可以不给，右栏就写摘要 |
| 操作 | 处理这件事的办法，每个有一个去处：一个页面、一个弹窗，或当场做完的一件事（如重新搜索）。可以没有（只是告知） |
| 去处 | 按确定后去的地方：一个页面或一个弹窗。可以没有（只是告知） |
| 看过 | 在电视的通知弹窗或手机控制台的通知列表里显示到屏幕上过（一行露出一半以上）。一页放不下的，翻到才算 |
| 新的 | 没看过的。同一个键的通知时间变晚了（事情有了变化）也算新的 |
| 时间 | 事情发生的时刻。跟着状态的通知不知道状态从什么时候起的，用这个用户档第一次看到它的时刻；它消失后再出现是新的一次 |

## 4. 规则

1. **一条通知 = 类别 + 标题 + 摘要 + 时间 + 说明与操作。** 列表一行写类别图标、标题与时间，下面一行摘要；聚焦时右栏写说明，列出处理它的几个操作。只有一个操作时不画按钮，按确定键直接执行它；有几个时按确定键或右键进右栏挑一个。没给说明的种类右栏写摘要，去处就是唯一的操作「查看」。
2. **同一件事只有一条。** 键相同、内容变了的再发，替换旧的，时间是这一次的，算新的；内容没变的再发不动。
3. **跟着状态的随状态走。** 在电视上、在控制台上处理掉，它都自己消失；状态又有了变化（如又有一条反馈有新回复），时间更新，算新的。
4. **看过 = 在电视的通知弹窗或手机控制台的通知列表里显示到屏幕上过。** 一页放不下的，翻到才算；没翻到的下次还是新的。两边是同一份：手机上看过的，电视上不再算新的。头像的红点 = 有新的通知。
5. **进应用时的几层一个关了下一个出，不叠在一起。** 更新后第一次打开先出本版新功能页；关掉后出控制台二维码弹窗（设置里开着「启动时弹出」、连着局域网时）；再关掉后，有没看过的通知就在右下角弹通知气泡（[5.1](#51-通知气泡)），不弹通知弹窗。
6. **正在用应用时来的通知：在首页才弹气泡。** 在首页、上面没有别的层时弹通知气泡；在播放、详情页、设置里只亮红点，回到首页再弹。应用开着时取到的发版后的通知（每次进应用都取一次，之后一小时左右取一次，从别的页退回首页时离上次超过 10 分钟也取，见 `remote-files.md`）、新版本（在前台时每 10 分钟看一眼、离上次超过 1 小时才查）也是这样。
7. **按用户档。** 每个用户档有自己的通知与看没看过；整机的事（如自动下载暂停）每个档都列，各档各记看没看过。
8. **进得来的只有「用户不在场时发生、会想知道或要做决定」的事。** 加一种通知前先对这一条。
9. **手机上能处理的在手机上处理，不能的「在电视上打开」。** 每种通知可以有一个控制台上的去处；没有的，在手机上点了让电视打开它在电视上的去处。

## 5. 通知弹窗

### 5.1 通知气泡

有没看过的通知时，在右下角弹一个气泡（同下载新版本时那张卡的位置与样子）：标题「有 N 条新通知」，下面一条一行列这几条通知的标题（前面一个点；至多 4 条，再多写「还有 N 条」），两颗按钮「查看」「关闭」。出来时焦点在「查看」上，焦点锁在气泡里；按「查看」打开通知弹窗，气泡不关，只是弹窗开着时先不画（弹窗面板半透明，气泡的字会透在后面）：关掉通知弹窗回到气泡，焦点回到「查看」，20 秒重新计；从通知里跳去了别的页面的，气泡收起。按「关闭」或返回键关掉，20 秒没动作自己消失（窗口被别的窗口盖着时不计时）。气泡只是提示，不算看过；在通知弹窗里看过了，回到气泡时它照旧写着刚才那几条。

什么时候弹（都要在首页、上面没有别的层：引导、选人、本版新功能、控制台二维码、通知弹窗、下载新版本的卡都不在；设置「有新通知时弹出提示」开着）：

- 进应用：冷启动、从后台回到前台、切换了用户档，有没看过的通知；冷启动时在本版新功能页、控制台二维码弹窗都关掉之后；
- 用着应用时来了新的一条（没看过的里多了一条，或同一条的时间变晚了）；不在首页的（播放、详情页、设置里）等回到首页。

同一批只弹一次：气泡关掉后，这些没看过的不再弹，直到来了新的一条（气泡在场时来了新的一条，换成新的这一批）；冷启动后重新算。从主屏的「继续观看」直接进播放器的，等回到首页。

### 5.2 样子

设计稿：[通知中心排法 · 11-21 左右两栏](https://claude.ai/artifact/YcP2iASQGmRmzmTPYEbx2e#page-v2)（第一页是更早的排法）。

```
┌ 通知 ──────────────────────────────┬────────────────────────────────────────┐
│ 新通知                              │ [更新] 10 月 24 日                       │
│ (反)● 反馈有新回复          3 分钟前 │ 新版本 1.0.8                             │
│      播放时偶尔卡顿                  │ • 可能要重新登录 Bangumi                  │
│ 之前的                              │   换了处理 Bangumi 授权的应用，……          │
│ (更)  新版本 1.0.8        10 月 24 日 │ • 加密直连                               │
│      可能要重新登录 Bangumi          │   连不上 Bangumi 官方时先走加密直连，……     │
│                                    │                                        │
│ 之后可在「设置」>「账号」>「通知」中查看 │ [自动更新] [查看详情]                     │
│                                    │ 按确定键选择操作                          │
└────────────────────────────────────┴────────────────────────────────────────┘
```

- 左边列表、右边一栏，中间一条竖线。两栏一样高，高固定：焦点换一条时弹窗不跟着变高变矮；列表、正文放不下时各自滚。末行提示钉在列表下面，不跟着滚。
- 一条一行：左边类别图标，没看过的图标右上角一个红点；标题（一行截断）与时间（今天的写「刚刚 / N 分钟前 / N 小时前」，昨天写「昨天」，今年的写月日，更早的写年月日）；下面一行摘要（一行截断，没有就不写）。
- 先后：新的在前；同是新的或同是看过的，跟着状态的在前，再按时间新的在前。弹窗开着时照打开那一刻的先后，不因为打开后都算看过而重排。
- 新的与看过的都有时分两段，各一行小标题「新通知」「之前的」（同常见的「新 / 更早」）；只有一种时不写。
- 一打开焦点在第一条。
- 从别处处理某一条（如手机控制台的「在电视上打开」）：只有一个操作的直接做，不打开通知列表（弹窗叠在当时的页面上，关掉回到原处）；几个操作的打开通知列表，焦点在那一条的第一个操作上（按左键回到那一条）。
- 右栏写焦点所在那一条（`TvNoticeKind.detail`）：类别签与时间，标题（大字），标题下面一行是哪一个（作品、反馈；不关哪一个的没有），正文几段（一段可以带小标题，要点前面一个点），外部链接的二维码，再是操作；种类没给说明的，正文写摘要：
  - 没有操作（只是告知）：只写正文。
  - 一个操作：不画按钮，最后一行写「按确定键」接这个操作（如「按确定键查看」）；在列表里按确定键直接执行它。有触摸屏的（平板模式，`LocalTvTouchInputEnabled`）没有确定键可按，这一个也画成按钮，同几个操作时一样点。
  - 两个操作：横排，主操作在左（从列表按右键进来先碰到最左一颗），左右键在两颗之间走；三个以上一颗一行竖着排。最后一行写「按确定键选择操作」；在列表里按确定键或右键，焦点到第一颗，这时最后一行写「按确定键」接聚焦的那一颗、「按左键返回通知列表」，列表里那一条铺浅底表示右栏说的是它。在最左一颗（竖排时任一颗）按左键或在右栏按返回键回到那一条。
- 正文里资源名这类长串（种类在 `TvNoticeParagraph.longName` 标出）在触屏上截到三行：那里操作画成按钮，写全会把按钮挤出右栏；电视上照常写全。摘要类的（如新版本一项改动的说明）两边都截（`TvNoticeParagraph.maxLines`），全文去操作里看。
- 说明照文案标准写（参照苹果提醒弹窗、Windows 错误提示的写法）：怎么了 → 为什么（应用为什么没有自己处理）→ 能做什么；完整的书面句子，不用「你」「应用」作主语；按钮只写动作，不在按钮下面配解释，选哪个的条件写进说明。
- 操作去的地方：
  - 弹窗的，叠在通知弹窗上面，关掉回到列表：焦点落回打开它的地方（在右栏几颗里挑的，落回那一颗，如新版本的「查看详情」；在列表里按确定键开的，落回那一条）。
  - 页面的，跳过去；在那页按返回回到打开通知时的那一页（首页，或设置的账号页），还有通知时弹窗重新打开，焦点在刚才那一条（它处理掉了就落在下一条）；处理掉的是最后一条就不再打开。
  - 当场做完的，做完弹一条提示，留在列表。
- 显示到屏幕上的算看过：一打开屏幕上那几条就算；放不下的往下翻到才算，没翻到的关掉后还带着点，下次打开仍在「新通知」里。按返回关掉弹窗。
- 没有通知时（手动打开）写「暂无通知」。
- 「之后可在『设置』>『账号』>『通知』中查看」在列表最后一行。通知弹窗里不放控制台的码：进应用时控制台二维码弹窗先出（规则 5），平时长按播放键在右上角调出控制台的码。

### 5.3 手动打开

- 入口在设置的账号页（主页点头像就到这一页）：「通知」一行，行尾写「N 条新通知」（没有新的不写），按确定键打开同一个通知弹窗，叠在设置页上，关掉回到这一行。
- 账号页从上到下：Bangumi 登录（没登录时；头像这时写「登录」，点进来就是它）→ 通知 → 我的反馈 → 账号设置（账号本身的设置收成一组：用户、Bangumi 账号是谁与退出登录、本地用户的转换与清除记录）→ 注册与登录的常见问题（没登录时）。登录那一节在上面时，「通知」前面加一行组标题「我的」。
- 有新的通知时头像右上角一个红点；只用红点，不写数字。这时点头像，焦点直接落在「通知」那一行；没有新的时照常落在第一行。头像上方浮出的按钮只有「播放记录」。
- 头像只在主页的侧边栏上有；搜索、详情页的侧边栏没有头像。新的通知只在首页自动弹，所以够用。

## 6. 手机控制台

### 6.1 通知列表

- 控制台顶栏「?」左边一颗铃铛「通知」，有新的通知时带红点（同电视头像上的点，两边一致）。点开是通知列表（全屏面板，同使用说明），与电视上同一份、同样的先后与分段。
- 一条一行：新的前面一个点、标题（加粗）、摘要（至多两行）、时间，同一行小字写点了会怎样：「在手机上处理」或「在电视上打开」；都没有的（只是告知）不写。
- 点一条：
  - 这种通知有控制台去处的，去控制台的那一页（如反馈去控制台的「反馈」那一条）；
  - 没有控制台去处、有电视上的操作的，电视上处理这一条（同[样子](#52-样子)里「从别处处理某一条」：一个操作的直接做，几个的打开通知列表、焦点在第一个操作上；电视当时没显示 Izuko 时，照控制台别的操作一样把 Izuko 叫到前台）；
  - 都没有的不动。
- 显示到屏幕上的才算看过（规则 4，滑到才算），电视下次进应用不为它们弹。
- 地址带 `#notices` 的，网页一打开就是通知列表。

### 6.2 实时提示

- 控制台页面开着、在前台时，电视上来了新通知，手机上当场在顶上弹一条横幅：「新通知：标题 · 摘要」，点了打开通知列表，8 秒后自己收起。几条一起来时写「N 条新通知」。打开网页时已有的新通知只亮红点，不弹横幅。电视上通知弹窗开着、新到的显示在屏幕上时已经算看过，手机上也不弹。
- 提示只是提醒，不算看过；在列表里显示到屏幕上才算。
- 电视上在播放时照常播放，不弹任何东西（规则 6）；用户在手机上处理完，电视下次进应用时这些已经看过、不弹。
- 控制台页面关着或在后台时手机上不提示（浏览器不让后台页面联网，也发不了系统通知），这时照电视上的规则：下次进应用弹。
- 每台手机可以在控制台的「设置 → 这台手机 → 新通知提示」里选不提示（记在这台手机的浏览器里，默认提示）。

### 6.3 现有的事在控制台上的去处

| 事 | 控制台上 |
|---|---|
| 反馈有新回复或处理结果 | 控制台「反馈」里的这一条 |
| 本地档登录后留下的收藏 | 在电视上打开（控制台的「账号与用户」里另有同样的合并 / 删除提示） |
| 发版后的「## 通知」 | 只是告知；说明里的 https 链接在网页上是可点的链接；有应用内操作的「在电视上打开」 |
| 订阅的几种（订阅分支） | 控制台上有对应页面的去那里，没有的在电视上打开 |

## 7. 设置

| 项 | 范围 | 默认 | 位置 |
|---|---|---|---|
| 有新通知时弹出提示 | 用户档 | 开 | 设置「界面」，紧挨「启动时弹出 Web 控制台」 |
| 新通知提示 | 这台手机（浏览器里） | 提示 | 控制台「设置 → 这台手机」 |

关着时不弹通知气泡，头像红点照常。

## 8. 现有的事怎么接

| 事 | 类 | 标题 / 摘要 | 去处 | 代替的旧提示 |
|---|---|---|---|---|
| 反馈有新回复或处理结果 | 跟着状态（一条反馈有未读就一条，键是这条反馈；时间是维护者最近一条回复或工单更新的时刻） | 「反馈有新回复」「反馈已处理」/ 反馈的标题；类别反馈 | 设置里的「我的反馈」（直接进那一组，进去就算看过）；右栏写维护者最近一条回复（至多 8 行，全文与附件在「我的反馈」里）、处理完了的写处理结果 | 头像红点（意思变成「有新的通知」） |
| 本地档登录后留下的收藏（登录着时） | 跟着状态（有待处理的就一条） | 「本地收藏待处理」/「N 部作品」；类别收藏 | 合并 / 删除的弹窗 | 回首页时自己找时机弹的窗口（去掉） |
| 有新版本 | 跟着状态（检查到更新的新版本时一条，键带版本号与这次启动的时刻：每次进应用都算新的、弹一次气泡，没更新就下次进应用再提醒（同系统设置上的更新角标：装上之前一直提醒）；开始下载后不列，下载失败又列出来） | 「新版本 1.0.9」/ 第一项改动的名字；类别更新 | 右栏：主要改动一项一个小标题与一句说明（一行截断，全文在「查看详情」里），要加群时那句提示；两个操作：「自动更新」（开始下载，通知弹窗与气泡收起、露出右下角的下载卡；这张卡挂在电视界面最外层，哪一页都在，播放时不画、下好了也等退出播放再装；下载进度、下好后「安装」、失败「重试」在右下角那张卡上；排在前面，进右栏焦点先落它）与「查看详情」（更新内容弹窗）；控制台上去「设置」里的应用更新 | 右下角的新版本提示卡（去掉，那张卡只在下载、安装时出现） |
| 发版后的「## 通知」 | 跟着状态（当前版本的通知一句一条，键是版本与内容） | 冒号前半句 / 后半句；类别公告 | 没有链接时只是告知：右栏正文写后半句，列表里截掉的在右栏看得全；应用内链接是操作按钮，https 链接画成二维码（写法见下） | 只显示通知的那一整页、本版新功能页（启动时与设置里）上的通知卡片（都去掉：只在通知里显示） |

通知只读加密的那份：release `notices` 的附件，只给装了应用的人看，每条注明给哪些版本，改了当场生效（`scripts/release-notice.py … --sealed`）。release 正文里的「## 通知」只给没有这套代码的旧版（1.0.9-alpha04 及以前），新版本不读。

一条的写法（解析在 `TvNoticeMarkup`，一句一行，`scripts/release-notice.py` 写入时检查链接）：

- 「标题：说明」，冒号前 30 字以内才拆；说明里写 `
` 分段；`**文字**` 标粗。
- 链接 `[文字](网址)`：
  - `https://…`：电视上在说明下面画二维码，码下写「文字」；触屏上是一颗在浏览器里打开的按钮；手机控制台上是可点的链接。一条只画第一个。
  - 应用内地址是右栏的一颗操作按钮（最多三颗），按钮上写「文字」：`ani://subjects/条目id` 条目详情；`ani://settings/分类[/行]` 设置的一类（账号写 `account`），落在那一行（锚点，如 `ani://settings/about/chat-groups` 是关于页的交流群）；`ani://whatsnew` 本版新功能。
  - 其他（`http`、写错的）只留文字，不出按钮。自己占一段的链接不再写成文字。

本版新功能页照旧是升级后第一次打开时盖的一整页：做成整页正是因为一句话的提示会被随手点掉，新功能没人看到。

订阅接上以后的（在订阅分支上做，见那边的订阅产品设计 `media/subscription-design.md`）：

| 事 | 类 | 标题 / 摘要 | 去处 |
|---|---|---|---|
| 订阅着的作品出了续集 | 消息 | 「「A」的续集「B」已公布」 | B 的订阅弹窗 |
| 在别的设备上把收藏改成了联动清单里的状态 | 消息 | 「在其他设备上将「X」标为在看」 | X 的订阅弹窗 |
| 订阅要处理（等选版本、版本断更、没找到等） | 跟着状态（一部作品一条） | 「「X」找到了版本，请选择」等 | 订阅详情或版本列表 |
| 自动下载整个暂停 | 跟着状态（整机的事，每个档都列） | 「存储设备未连接，自动下载已暂停」等 | 能解决它的设置页 |

## 9. 接口

数据（app-data）：

```kotlin
// data/models/notice/Notice.kt: 存下来的都是字符串, 不存显示的字
@Serializable
data class Notice(
    val kind: String,                           // 种类 id, 如 "feedback.reply"; 界面认不出的不列
    val key: String,                            // 这件事的键; 同一个键只有一条
    val atMillis: Long,                         // 时间; 同一个键的时间变晚算新的; 不知道时给 Notices.UNKNOWN_TIME
    val args: Map<String, String> = emptyMap(), // 文案与去处要用的参数
)

// domain/notice/Notices.kt: 一个用户档的通知 (存在这个档的设置里), Koin 单例
class Notices {
    suspend fun post(notice: Notice)            // 发一条消息; 同键内容没变不动, 变了替换
    suspend fun retract(key: String)            // 撤回一条消息
    fun addSource(source: Flow<List<Notice>>)   // 接上一个跟着状态的来源 (一个进程一次)
    val all: Flow<List<NoticeEntry>>            // 消息 + 各来源的, 带看没看过, 排好先后
    suspend fun markSeen(notices: Collection<Notice>)
}

data class NoticeEntry(val notice: Notice, val pending: Boolean /* 跟着状态的 */, val seen: Boolean)
```

界面（ui-tv，`ui/notice`）：

```kotlin
/** 一种通知: 类别、标题与摘要、右栏的说明与操作. 一个种类一个文件, 在 TvNotices 的种类表里登记一行 */
interface TvNoticeKind {
    val id: String
    val category: TvNoticeCategory                      // 列表行左边的图标、右栏的类别签
    fun source(): Flow<List<Notice>>? = null            // 跟着状态的来源; 只发消息的为 null
    suspend fun title(notice: Notice): String?          // 标题 (在电视上算, 控制台也用它); null = 不列
    suspend fun summary(notice: Notice): String? = null // 列表里标题下面那一行; null = 没有
    fun textChanges(): Flow<*>? = null                  // 标题、摘要与说明还看的状态, 一变全部重算; 只看通知本身的为 null
    fun destination(notice: Notice): TvNoticeDestination?
    suspend fun detail(notice: Notice): TvNoticeDetail? = null  // 右栏的说明与操作; null = 右栏写摘要, 有去处时一个操作「查看」去那里
    fun consoleHref(notice: Notice): String? = null     // 控制台上的去处, 如 "#settings/feedback"
}

/** 右栏: 正文几段、处理它的操作 (一个时按确定键直接做, 几个时进右栏挑)、哪一个 (作品、反馈)、外部链接 (二维码) */
class TvNoticeDetail(val body: List<TvNoticeParagraph>, val actions: List<TvNoticeAction>, val subject: String? = null, val qr: TvNoticeQr? = null)
/** 正文一段: 字 (可带粗体)、小标题、要点前面的点、至多几行 (摘要类)、资源名这类长串 (触屏上截到三行) */
class TvNoticeParagraph(val text: AnnotatedString, val title: String? = null, val bullet: Boolean = false, val maxLines: Int = Int.MAX_VALUE, val longName: Boolean = false)
class TvNoticeAction(val label: String, val destination: TvNoticeDestination)

sealed interface TvNoticeDestination {
    class Page(val navigate: (AniNavigator) -> Unit)                        // 跳到一页
    class Dialog(val content: @Composable (onDismiss: () -> Unit) -> Unit)  // 叠在通知弹窗上
    class Run(val run: suspend (Toaster) -> Unit)                           // 当场做完, 留在列表
}
```

- **接一种新的事**：
  1. 在 ui-tv 写一个 `TvNoticeKind`；
  2. 在 `TvNotices` 的种类表里登记一行；
  3. 消息在事件发生处 `Notices.post`；跟着状态的由种类的 `source()` 给出（来源不知道时间时给 `Notices.UNKNOWN_TIME`）。
- **存储**：消息、看过的记录、不知道时间的那几条第一次出现的时刻，按用户档存在设置里（`SettingsRepository.notices`，换用户是重启进程）。
- **认不出的种类**（降级后读到新版本存的）不列，留到过期清掉。参数都是字符串，以后加取值不影响旧版本读。
- **从别处处理一条**：`TvNotices.handle(key)`。只有一个操作的直接做（弹窗由 `TvNoticeHost` 直接叠在当时的页面上，不开列表），几个的打开通知列表、焦点在它的第一个操作上（`TvNoticeDialogState.focusAction`）；列表还没算出来或这一条已经不在时，打开列表、焦点在它原来的位置。
- **控制台**：`GET api/notices` 列表（标题、摘要、时间、新不新、跟不跟状态、控制台去处、有没有电视去处）；`POST api/notices/seen`（`key` 可多个）标看过；`POST api/notices/open`（`key`）让电视处理一条（`TvNotices.handle`），先把 Izuko 叫回前台。实时提示搭在网页每 2 秒一次的 `api/notice` 上：回包的 `notices` 里有新的几条（标题与摘要）与条数。
- **调试**（debug 包）：`GET api/debug/notices` 看列表（类别、标题、摘要、右栏正文与操作）与弹窗开没开；`POST api/debug/notices/post`（`kind`、`key`、`arg.<名>`）发一条消息；`POST api/debug/notices/release`（`title` 可多个）换掉当前版本的「## 通知」；`POST api/debug/notices/clear` 撤回全部消息；`POST api/debug/notices/open` 打开通知弹窗；`POST api/debug/notices/foreground` 当作刚从后台回到前台。

## 10. 取舍

**弹窗，不做单独一页。** 电视上手动进一页要先进侧边栏再找；通知又多半是进应用时看一眼。弹窗不占导航，去处是弹窗的直接叠在上面，处理完回到列表。

**入口在设置的账号页，不占侧边栏一项；红点挂在头像上。** 进应用会自动弹、平时有红点，手动打开用得少，不值得在侧边栏上常驻一项。做法同 Fire TV 把通知中心放在「设置」里、有新的时在「设置」上挂标记：红点挂在通向通知的入口（头像 → 账号页）上，点进去就是「通知」那一行。账号页里账号本身的设置收成「账号设置」一组，账号页最外一层只放登录、通知、我的反馈这几样常用的。

**只在有新的时弹，不是有就弹。** 看过而故意不处理的事（如有意拔掉外接盘）每次都弹，就是每次进应用都要先关一个窗。气泡关掉后同一批也不再弹，来了新的才弹。

**进应用时的弹窗一个关了下一个出，通知用气泡。** 控制台二维码是连手机的入口，每次进应用都该看得到，通知弹窗里不再另放一个码；通知与新版本都不急，用右下角的气泡提一句，用户想看再按「查看」，不用连着关几个窗。新版本做成一条通知，不再单独出一张提示卡：它和别的通知一样在列表里留着、手机上看得到，右下角只剩一个气泡。本版新功能页只在更新后第一次打开时出，排在最前，关掉后照常出二维码与气泡。

**手机上实时提示，不加「连着手机时电视不弹」的开关。** 电视只在首页弹气泡，播放时不打断；手机上看过的电视就不再弹。两条规则合起来已经是「连着手机就在手机上处理」，不需要再有一个开关。

**不复用上游的站内通知。** 上游的通知由 Ani 服务器下发（评论回复、举报结果、账号安全、公告），去处只有剧集、条目、人物、评论与网页，也没有电视界面；本项目不用 Ani 服务器，这套已经删了。借了它的三点：认识的种类用自己的文案、入口只用红点不写数字、会加取值的字段存字符串。
