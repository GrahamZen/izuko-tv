# 通知

本文定应用内通知的行为与接口：哪些事进通知、什么时候弹、怎么接一种新的事。

## 1. 一句话

**后台发生的、用户要知道或要处理的事汇成一个列表。每条一个标题与一行摘要，按确定去处理它的那一页或弹窗。** 每次进应用有没看过的就弹一次，平时在侧边栏的「通知」上亮红点，点里写着没看过的条数。手机控制台上有同一份列表；控制台开着时新通知当场在手机上提示，播放时也能在手机上处理。

## 2. 目标与不做的

### 目标

| 编号 | 目标 |
|---|---|
| G1 | 用户不用记各种事去哪里看：反馈的回复、待处理的收藏、发版后的通知、订阅要处理的事都在一处 |
| G2 | 电视上不用手动找：进应用时有没看过的通知就自动弹出来 |
| G3 | 每次进应用最多被打断一次 |
| G4 | 接一种新的事只要三步：写一个种类、登记一行、在事件发生处发出去（或接上状态） |
| G5 | 在哪里处理掉的（电视上、手机控制台），通知都跟着消失 |
| G6 | 电视在播放时不被打断，用户也能当场在手机上看到并处理新通知 |

### 不做的

| 不做 | 原因 |
|---|---|
| 系统通知（通知栏） | 电视上的系统通知不好用，多数用户看不到。手机上也发不了：控制台是局域网里的 http 页面，浏览器不让这种页面发系统通知 |
| 服务器推送 | 应用不依赖自己的服务器；通知都由这台电视上的事产生 |
| 列表一行里放按钮 | 一行只写标题与摘要；说明与操作在右栏，聚焦那一条时才出现 |
| 进度类的消息（每集下好了、同步完成） | 发生得多、不用处理；订阅页的点、各页面的状态已经说了 |
| 图片、详情页 | 一条的说明在右栏几句话说完；要细看的去去处看 |

## 3. 概念

| 词 | 意思 |
|---|---|
| 通知 | 一条：种类、键、参数、时间。显示的标题、摘要与去处由种类决定 |
| 种类 | 一类事，如「反馈有新回复」。每个种类定文案与去处 |
| 类别 | 列表行左边的图标、右栏标题上面的签：公告、更新、反馈、收藏（订阅分支还有订阅、下载）。按处理它要去哪一处分，图标取侧边栏、设置里同一处已有的 |
| 封面 | 通知说的是哪一部作品时（种类给了 `TvNoticeKind.cover`），左边不画类别图标，画这部作品的竖版封面；还没取到、取不到时还是类别图标。说的不是某一部作品的（新版本、公告、反馈、待处理的本地收藏）照旧画图标 |
| 标题 | 怎么了，短到一行放得下（如「反馈有新回复」「新版本 1.0.9」）。列表、电视与手机上的横幅都写它 |
| 摘要 | 列表里标题下面那一行：是哪一个（作品、反馈），或说明的开头（如公告冒号后面那半句）。可以没有 |
| 键 | 这一件事的标识。同一个键只有一条 |
| 跟着状态的 | 一个状态在它就在、状态没了它自己消失的通知（如有本地收藏待处理、这一版有发版后的通知）。不存，每次从状态算 |
| 消息 | 发生过的一件事（如续集公布）：存下来，看过算读，30 天后或超过 100 条时最早的清掉 |
| 说明 | 聚焦一条时右栏写的：怎么了、为什么、能做什么，几句完整的书面句子；可以分几段，一段可以带小标题（如新版本里一项改动的名字）。种类可以不给，右栏就写摘要 |
| 操作 | 处理这件事的办法，每个有一个去处：一个页面、一个弹窗，或当场做完的一件事（如重新搜索）。可以没有（只是告知） |
| 去处 | 按确定后去的地方：一个页面或一个弹窗。可以没有（只是告知） |
| 看过 | 列出来过：打开过电视的通知弹窗（列出来的都算），或在手机控制台的通知列表里显示到屏幕上过 |
| 读过 | 内容显示出来过：电视通知弹窗右栏说这一条说满 1 秒（焦点停在它上面，同点开看了；按着方向键一行行划过去的不算），手机控制台的列表里显示到屏幕上过（那里整条字都写着），或在它上面做过操作（弹窗里的操作、横幅上短按）。读过的都算看过 |
| 新的 | 没看过的。同一个键的通知时间变晚了（事情有了变化）也算新的，也重新算没读过 |
| 时间 | 事情发生的时刻。跟着状态的通知不知道状态从什么时候起的，用这个用户档第一次看到它的时刻；它消失后再出现是新的一次 |

## 4. 规则

1. **一条通知 = 类别 + 标题 + 摘要 + 时间 + 说明与操作。** 列表一行写类别图标（说的是哪一部作品的画它的封面）、标题与时间，下面一行摘要；聚焦时右栏写说明，列出处理它的几个操作。操作都画成按钮（只有一个也画）；在列表里按确定键同右键，进右栏落在第一颗，在按钮上按确定才执行（同常见的左右两栏：左边按确定是选中，误按不出事；一按就做的捷径在横幅上，见 5.1）。没给说明的种类右栏写摘要，去处就是唯一的操作「查看」。
2. **同一件事只有一条。** 键相同、内容变了的再发，替换旧的，时间是这一次的，算新的；内容没变的再发不动。
3. **跟着状态的随状态走。** 在电视上、在控制台上处理掉，它都自己消失；状态又有了变化（如待处理的本地收藏又多了），时间更新，算新的。
4. **看过与读过分两步（同手机系统与常见应用的通知中心）。** 侧边栏「通知」上的数字 = 新来的（没看过的），打开通知弹窗就清掉；列表里一行前面的点 = 没读过，焦点在它上面停一会儿（右栏把说明写出来了，同点开看了）或在它上面做了操作才灭。只是打开弹窗扫一眼，点都还在，下次打开仍在「新通知」里。两边是同一份：手机上看过、读过的，电视上也算。
5. **进应用时的几层一个关了下一个出，不叠在一起。** 更新后第一次打开先出本版新功能页；关掉后出控制台二维码弹窗（设置里开着「启动时弹出」、连着局域网时）；再关掉后，有没看过的通知就在右上角弹通知横幅（[5.1](#51-通知横幅)），不弹通知弹窗。
6. **正在用应用时来的通知：在有侧边栏的页面才弹横幅。** 侧边栏上有「通知」的页面——首页、搜索结果、条目详情页的首屏——上面没有别的层时弹通知横幅：铃铛上的红点和横幅说的是同一件事，看得到铃铛的地方就弹。在播放、设置里，在搜索页挑关键词时（横幅会拿走输入框的焦点），在详情页翻离首屏后（侧边栏不在了）只亮红点，回到有侧边栏的页面再弹。应用开着时取到的发版后的通知（每次进应用都取一次，之后一小时左右取一次，从别的页退回首页时离上次超过 10 分钟也取，见 `remote-files.md`）、新版本（在前台时每 10 分钟看一眼、离上次超过 1 小时才查）也是这样。
7. **按用户档。** 每个用户档有自己的通知与看没看过；整机的事（如自动下载暂停）每个档都列，各档各记看没看过。
8. **进得来的只有「用户不在场时发生、会想知道或要做决定」的事。** 加一种通知前先对这一条。
9. **手机上能处理的在手机上处理，不能的「在电视上打开」。** 每种通知可以有一个控制台上的去处；没有的，在手机上点了让电视打开通知、停在这一条（手机列表上没写会做什么，看说明、挑操作都在电视上）。

## 5. 通知弹窗

### 5.1 通知横幅

设计稿：[11-23 通知横幅](https://claude.ai/artifact/YcP2iASQGmRmzmTPYEbx2e#page-v7)。

有没看过的通知时，在页面右上角弹一条横幅（哪些页面见规则 6；样子照 tvOS 的系统提醒）：约 320×72dp 的小圆角条（宽度跟着两行字里长的那一行走，最窄 320dp、最宽 480dp），底色同首页没聚焦的按钮（深色是深灰，不用主题色），带一点阴影；左边一个淡底方块里放第一条通知的类别图标（它说的是哪一部作品时放这部作品的封面，竖版海报裁成方的），右边两行，写的是第一条通知。它说的是哪一部作品时：第一行作品名，第二行这件事、后面接淡一档的怎么按（「作品名」/「标题 · 按确定键查看，长按查看详情」：先说是谁、再说怎么了）；别的：第一行标题，第二行淡一档写怎么按。怎么按 ——第一条有默认操作时写短按做什么、长按看更多（「按确定键查看，长按查看详情」，几条时前面加「还有 N 条 · 」）；没有默认操作的写「按确定键查看」，几条写「还有 N 条 · 按确定键查看」（短按、长按都是打开通知弹窗）。到了最宽还放不下时，第一行滚着读完（横幅在场时焦点在它身上，同别处聚焦的那一项；视觉效果设成不滚跑马灯的档时截尾），第二行截的是末尾的怎么按，这件事一直看得到。不写摘要，不放红色数字。横幅本身就是一颗按钮，没有「查看」「关闭」：

- 出来时焦点在横幅上；按方向键横幅当场收起（同按返回），焦点回到页面上原来那一项，这一下不往页面里传，再按才在页面上走（不锁着方向键等 10 秒：常见电视系统的提醒都不挡方向键）；
- 短按确定做第一条的默认操作（见下），这一条算读过，横幅收起：如本地收藏待处理直接打开合并 / 删除的弹窗（叠在当时的页面上，不开通知列表，关掉回到原处）。横幅刚出来 0.5 秒内的短按不算：横幅是突然弹出来抢了焦点的，那一下多半是按给下面页面的。第一条没有默认操作的，短按同长按；
- 长按确定（按住约 0.4 秒，同海报卡长按出菜单，不用等松手）打开通知弹窗，横幅收起：只有一条开到那一条；这一批都在别的签里看（如都是反馈回复）开到那个签的第一条；不然开「通知」签。看说明、挑别的操作、看其余几条都在这里；
- 触屏上（平板）点一下同短按，长按同长按；
- 按返回关掉；10 秒没动作自己淡出，焦点回到原来那里（窗口被别的窗口盖着时不计时）；
- 横幅只是提示，不算看过，收起后侧边栏「通知」照旧亮红点；横幅在场时去了没有侧边栏的页面的（如从手机上点了播放），横幅收起。

默认操作是这一条的第一个操作，种类标了它能一按就做时（`TvNoticeAction.quick`，同时给横幅上写的短的动作名）；第一个不能的不往后找。能一按就做的是打开挑的弹窗、跳到一页、打开一个列表这类，做错了按返回就回来：收藏待处理的「查看」，没给说明的种类的「查看」（去处就是它）。不能的是一按就改了数据、开始下载安装、要先看说明的：新版本的「自动更新」；公告的链接、反馈回复（它的去处本来就是打开通知弹窗）也不设。

横幅上写按键提示，通知弹窗里不写：横幅是突然弹出来、又抢了焦点的，不写的话不一定知道按什么（Apple TV 要按键的提醒也写按哪个键）。

什么时候弹（都要在有侧边栏的页面、上面没有别的层：引导、选人、本版新功能、控制台二维码、通知弹窗、下载新版本的卡都不在；设置「有新通知时弹出提示」开着）：

- 进应用：冷启动、从后台回到前台、切换了用户档，有没看过的通知；冷启动时在本版新功能页、控制台二维码弹窗都关掉之后；
- 用着应用时来了新的一条（没看过的里多了一条，或同一条的时间变晚了）；眼前这一页没有侧边栏的（播放、设置里，搜索页挑关键词时，详情页翻离首屏后）等回到有侧边栏的页面。

同一批只弹一次：横幅收起后，这些没看过的不再弹，直到来了新的一条（横幅在场时来了新的一条，换成新的这一批）。下次进应用（冷启动、从后台回到前台）时还有没看过的，再弹一次。从主屏的「继续观看」直接进播放器的，等回到有侧边栏的页面。

### 5.2 样子

设计稿：[通知中心排法 · 11-21 左右两栏](https://claude.ai/artifact/YcP2iASQGmRmzmTPYEbx2e#page-v2)（第一页是更早的排法）。

```
┌ 通知 ──────────────────────────────┬────────────────────────────────────────┐
│ 新通知                              │ [更新] 10 月 24 日                       │
│ (反)● 反馈有新回复          3 分钟前 │ 新版本 1.0.8                             │
│      播放时偶尔卡顿                  │ • 可能要重新登录 Bangumi                  │
│ 之前的                              │   换了处理 Bangumi 授权的应用，……          │
│ (更)  新版本 1.0.8        10 月 24 日 │ • 加密直连                               │
│      可能要重新登录 Bangumi          │   连不上 Bangumi 官方时先走加密直连，……     │
│                                    │                                        │
│                                    │ [自动更新]                              │
└────────────────────────────────────┴────────────────────────────────────────┘
```

- 左边列表、右边一栏，中间一条竖线。两栏一样高，高固定：焦点换一条时弹窗不跟着变高变矮；列表、正文放不下时各自滚，只画在自己那一栏里，被截住的那一头渐隐（列表滚上去的行不压到上面的签与「刷新」上）。不写按键提示（左列下面、右栏最后都不写）：按键照电视上的习惯走，看得出来。
- 一条一行：左边类别图标，没读过的图标右上角一个红点；说的是哪一部作品的左边画它的封面：竖的框（32×48dp，2:3，同竖版海报的比例，小圆角），红点在封面右上角。列表里有带封面的行时，没封面的行左边也留同样宽的一栏、行也一样高（字的起点对齐），这一栏离行的左边、离文字各 10dp（只画图标时是 14dp 与 12dp）：封面比图标宽出来的不把文字往右挤，文字的起点同原来差不多；一行带封面的都没有的列表（如「我的反馈」）照旧。NSFW 设置为隐藏或模糊时，NSFW 作品的封面打码（这是用户自己收藏的作品，不换回图标）；标题（一行截断）与时间（今天的写「刚刚 / N 分钟前 / N 小时前」，昨天写「昨天」，今年的写月日，更早的写年月日）；下面一行摘要（一行截断，没有就不写）。
- 先后：没读过的在前；同是没读过的或同是读过的，跟着状态的在前，再按时间新的在前。弹窗开着时照打开那一刻的先后，读了一条它不挪位置（只是点灭了）；开着时新来的排进「新通知」那一段。
- 打开时没读过的（与开着时新来的）和之前的都有时分两段，各一行小标题「新通知」「之前的」（同常见的「新 / 更早」）；只有一种时不写。
- 一打开焦点在第一条。
- 右栏写焦点所在那一条（`TvNoticeKind.detail`）：类别签与时间，标题（大字），标题下面一行是哪一个（作品、反馈；不关哪一个的没有），正文几段（一段可以带小标题，要点前面一个点），外部链接的二维码，再是操作；种类没给说明的，正文写摘要：
  - 没有操作（只是告知）：只写正文。正文放不下时（底下一截渐隐），在列表里按确定键或右键焦点进正文，上下键翻，左键或返回键回到那一条；放得下的按了不动。
  - 一个操作：也画成按钮（看得出会做什么）；在列表里按确定键同右键，进右栏落在它上面，再按确定才执行。行本身就是一件事的（`TvNoticeColumnItem.rowAction`，如触屏上的「写新反馈」）按确定键（触屏上点这一行）直接做。触屏上（平板模式，`LocalTvTouchInputEnabled`）点按钮。
  - 两个以上：排一行，各占自己的宽，主操作在左（从列表按确定键进来先到最左一颗），左右键在几颗之间走。一行放不下时（如发版后的通知里三颗应用内链接，或英文里长的按钮）这一行左右滚：焦点到哪颗滚到哪颗露全，截住的那一头渐隐；按钮上的字不截、不折行，也不拆成几行按钮（会把正文挤没）。在列表里按确定键或右键，焦点到第一颗，列表里那一条铺浅底表示右栏说的是它。在最左一颗按左键回到那一条；最右一颗按右键不动（不跨到别的签）。
- 触屏上（平板）右栏说的那一行铺浅底（同焦点在右栏按钮上时），看得出点的是哪一行。
- 正文里资源名这类长串（种类在 `TvNoticeParagraph.longName` 标出）在触屏上截到三行：那里操作画成按钮，写全会把按钮挤出右栏；电视上照常写全。摘要类的段可以两边都截（`TvNoticeParagraph.maxLines`），全文去操作里看。
- 说明照文案标准写（参照苹果提醒弹窗、Windows 错误提示的写法）：怎么了 → 为什么（应用为什么没有自己处理）→ 能做什么；完整的书面句子，不用「你」「应用」作主语；按钮只写动作，不在按钮下面配解释，选哪个的条件写进说明。
- 操作去的地方：
  - 弹窗的，叠在通知弹窗上面（通知弹窗不收起；小窗这一层不再压暗、是实底，下面的字不透上来；小窗开着时下面不画聚焦的样子，聚焦的那一行铺浅底），关掉回到下面：焦点还在打开它的地方（在右栏几颗里挑的是那一颗，如「我的反馈」里一张单的「在手机上补充」；在列表里按确定键开的是那一条）。弹窗里再跳页面的（经 `LocalTvNoticeOverlayHost`）同页面的：两层都收起，回来时通知弹窗重新打开、停在这一条。
  - 页面的，跳过去；在那页按返回回到打开通知时的那一页（一般是首页），还有通知时弹窗重新打开，焦点在刚才那一条（它处理掉了就落在下一条）；处理掉的是最后一条就不再打开。
  - 当场做完的，做完弹一条提示，留在列表。
- 一打开，列出来的都算看过（侧边栏「通知」上的数字清掉；开着时新来的也当场算）。右栏说一条说满 1 秒算读过，那一行前面的点灭掉；没读过的关掉后还带着点，下次打开仍在「新通知」里。按返回关掉弹窗。
- 没有通知时（手动打开）写「暂无通知」。
- 通知弹窗里不放控制台的码：进应用时控制台二维码弹窗先出（规则 5），平时长按播放键在右上角调出控制台的码。

### 5.3 手动打开

- 侧边栏单独一项「通知」（铃铛），在头像与「搜索」之间。主页、搜索页、详情页的侧边栏都有，位置不随有没有通知变。点它打开同一个通知弹窗，关掉后焦点回到这一项。
- 有新的通知时「通知」上画数字角标（见本节最后一条），打开通知弹窗就清掉。
- 头像管账号：点头像进设置的账号页（用户、Bangumi 登录与账号），旁边写昵称，没登录写「登录」；聚焦时上方浮出「播放记录」。
- 设置里不放通知的入口：通知只从这两处打开，侧边栏的「通知」与右上角的横幅。
- 侧边栏「通知」上的红点是数字角标：红底白字写没看过的通知有几条，10 条以上写「9+」，一条没看过的都没有时不画（横幅只写第一条与「还有 N 条」，收起后这里看得到还剩几条）。

### 5.4 签与右栏翻页

设计稿：[通知中心排法 · 11-22 我的反馈并进通知中心](https://claude.ai/artifact/YcP2iASQGmRmzmTPYEbx2e#page-v3)。

- 弹窗顶上一排签：「通知」在最前，后面是各功能登记的签（`TvNotices.tabs`，如「我的反馈」）；只有「通知」一个时不画签，照旧写标题「通知」。
- 签的样子同追番页的玻璃标签栏（照 tvOS 顶部标签栏，原生公共件 `TvNativeGlassTabBar`，尺寸与配色同 Compose 的 `TvCollectionGlassTab`）：一整条玻璃胶囊，没选中的字淡一些，选中的垫一块半透明片，聚焦的换成浅色实底配深色字、略放大并投一层影。签能聚焦（电视上）；触屏上点签换签、不画聚焦的样子。
- 顶栏右边是「刷新」（设计稿 [11-23 右上角刷新](https://claude.ai/artifact/YcP2iASQGmRmzmTPYEbx2e#page-v5)）：按钮左边一行小字（上次刷新的时间、在刷哪几样、刷完的结果、还要等多久），按钮是图标加字，聚焦时不铺底，图标与字变主色；冷却中变灰，正在刷新时图标转圈。只有「通知」一个签时同样有。从最右的签按右键到它，在它上面按左键回到选中的签、按下键进这个签的第一行（见下面的按键）；没画签时列表第一行按上键到它，左右键不动。刷哪几样、冷却多久见 `TvNoticeRefresh`。
- 签上的红点表示这个签里有没读过的。别的签要提醒的事照样发成通知，种类写明在哪个签里看（`TvNoticeKind.tab`，如反馈的回复在「我的反馈」）：这种通知不在「通知」签和手机控制台的通知里列，签上的红点就是它们有没读过；照样算侧边栏「通知」的数字与横幅（横幅上按确定开到那个签的那一行）；打开弹窗、焦点到那个签时算看过（`TvNoticeTab.onTabShown`），那个签的右栏写过它时算读过（`TvNoticeTab.onShown`）。
- 按键（照 Apple TV、Google TV 带顶部签的页面）：
  - 签上左右键换签，聚焦即选中、两栏当场换成那个签的（右栏说它的第一行）；到头不绕回，最右的签再按右键到「刷新」，「刷新」上按左键回到选中的签。
  - 签上按下键或确定键、「刷新」上按下键进内容：落在这个签的第一行（「通知」是第一条，「我的反馈」是「写新反馈」）。
  - 列表里上下键换行，第一行按上键到签；右键进右栏（见 5.2），左键不动。
  - 返回键：一次退一层——右栏（按钮、正文）里回到那一条；列表、签、「刷新」上关掉弹窗（通知弹窗是叠在页面上的一层，关掉代价小，再打开从第一条开始；同常见电视应用的面板）。有没有签都一样。
  - 长按返回键同别处的弹窗（关掉弹窗，再做设置里「长按返回键」那件事）。
- 签成了选中的那个时（换过去、打开时就在它）告诉那个签（`TvNoticeTab.onTabShown`），只在它里面提醒的通知由它标看过。
- 换签时新签的行还没取到的，旧签的两栏留到新签画出来，中间不空；这时按下键不动，取到了再进。
- 每个签里都是 5.2 的左右两栏：签给出列哪几行（分段的小标题、每行的图标与红点、右栏的签与小字、正文与操作），焦点与按键由弹窗管，行为同「通知」签。
- 打开到某个签的某一行：`TvNotices.open(tab = …, focusKey = …)`；那一行还不在（记录还没取到、已经删了）落在第一行。通知弹窗开着时调就是换过去。叠在上面的弹窗关掉、从去处页面回来，都回到那个签。
- 右栏翻页：焦点在按钮上按上下键翻正文，一下翻正文可见高度的约三分之二，按钮钉在底部，焦点不动；正文放得下时不动。
- 签可以要：
  - 正文一打开停在末尾（来往记录这类，最新的写在最下面）；一行可以另定（`TvNoticeColumnItem.bodyStartsAtEnd`，如「写新反馈」从开头看）；
  - 按了当场做完的操作，焦点留在按钮上，不跳回那一行（`buttonsForSingleAction`）。

  「通知」签两样都不要：当场做完的操作焦点回到那一行（按钮可能随它处理掉一起没了）。

## 6. 手机控制台

### 6.1 通知列表

- 控制台顶栏「?」左边一颗铃铛「通知」，有新的通知时带红点（亮不亮同电视侧边栏「通知」上的那个，两边一致；电视上的点里写着条数）。点开是通知列表（全屏面板，同使用说明），与电视上同一份、同样的先后与分段。
- 一条一行：没读过的前面一个点、标题（加粗）、摘要（至多两行）、时间，说的是哪一部作品的左边画它的封面（同电视上的竖框，点在封面右上角；封面经电视转发，拉不到换下一个候选地址；NSFW 作品糊掉），同一行小字写点了会怎样：「在手机上处理」或「在电视上打开」；都没有的（只是告知）不写。
- 点一条：
  - 这种通知有控制台去处的，去控制台的那一页；
  - 没有控制台去处、有电视上的操作的，电视上打开通知弹窗、焦点停在这一条（在别的签里看的开到那个签），右栏是它的说明与操作，在电视上挑；不直接做它的操作（只写了「在电视上打开」，没写会做什么）。电视当时没显示 Izuko 时，照控制台别的操作一样把 Izuko 叫到前台；
  - 都没有的不动。
- 显示到屏幕上的算读过（这里整条字都写着，同电视上右栏说过；滑到才算），电视下次进应用不为它们弹，电视通知弹窗里也不再带点。
- 地址带 `#notices` 的，网页一打开就是通知列表。

### 6.2 实时提示

- 控制台页面开着、在前台时，电视上来了新通知，手机上当场在顶上弹一条横幅：「新通知：标题 · 摘要」，点了打开通知列表，8 秒后自己收起。几条一起来时写「N 条新通知」。打开网页时已有的新通知只亮红点，不弹横幅。电视上通知弹窗开着时新到的列出来就算看过，手机上也不弹。
- 提示只是提醒，不算看过；在列表里显示到屏幕上才算。
- 电视上在播放时照常播放，不弹任何东西（规则 6）；用户在手机上处理完，电视下次进应用时这些已经看过、不弹。
- 控制台页面关着或在后台时手机上不提示（浏览器不让后台页面联网，也发不了系统通知），这时照电视上的规则：下次进应用弹。
- 每台手机可以在控制台的「设置 → 这台手机 → 新通知提示」里选不提示（记在这台手机的浏览器里，默认提示）。

### 6.3 现有的事在控制台上的去处

| 事 | 控制台上 |
|---|---|
| 本地档登录后留下的收藏 | 在电视上打开（控制台的「账号与用户」里另有同样的合并 / 删除提示） |
| 发版后的「## 通知」 | 只是告知；说明里的 https 链接在网页上是可点的链接；有应用内操作的「在电视上打开」 |
| 订阅的几种（订阅分支） | 控制台上有对应页面的去那里，没有的在电视上打开 |

## 8. 现有的事怎么接

| 事 | 类 | 标题 / 摘要 | 去处 | 代替的旧提示 |
|---|---|---|---|---|
| 反馈有新回复或处理结果 | 消息（查到时发：一张单一条，键是这张单；时间是维护者最近一条回复或工单更新的时刻，只多了一条回复也算新的；本机删了这张单就不列）。在「我的反馈」签里看：不在「通知」签和控制台的通知里列；「我的反馈」签上的红点提醒（没读过的），打开通知弹窗、焦点到这个签时算看过，在电视 / 控制台看过这张单时算读过 | 「反馈有新回复」「反馈已处理」/ 反馈的标题；类别反馈 | 「我的反馈」签里的这张单（横幅上按确定直接到那里） | 头像上的反馈红点；设置里的「我的反馈」；「通知」签里的反馈那一条 |
| 本地档登录后留下的收藏（登录着时） | 跟着状态（有待处理的就一条） | 「本地收藏待处理」/「N 部作品」；类别收藏 | 合并 / 删除的弹窗 | 回首页时自己找时机弹的窗口（去掉） |
| 有新版本 | 跟着状态（检查到更新的新版本时一条，键带版本号与这次启动的时刻：每次进应用都算新的、弹一次横幅，没更新就下次进应用再提醒（同系统设置上的更新角标：装上之前一直提醒）；装上之前一直列着，下载中、下好了、取消了都在） | 「新版本 1.0.9」/ 第一项改动的名字；类别更新 | 右栏：完整的更新内容（这一版「本次更新」以后的全部，一项改动一个小标题与说明、写全不截断，「已知问题」这类小节标题单独一行；落后几版时逐版写，每版前面一行版本号；焦点在按钮上时上下键翻），最后是「查看详情」：发布页，平板上是一颗在浏览器里打开的按钮，电视上（一般没有浏览器）是给手机扫的码，手机控制台上是链接；一个操作：「自动更新」（通知弹窗收起；还没下就开始下载，正在下载只看进度，下好了就安装。开始下载或看进度时动作面板弹出来、焦点在顶上下载的那一格：进度、✕（下载中是取消下载，下好了或失败了是「先不更新」：那一格收起），下好后「安装」、失败「重新下载」都在那里；按返回关掉面板，还在原来那一页）；控制台上去「设置」里的应用更新 | 右下角的新版本提示卡与下载卡（电视上都不画，下载在动作面板顶上） |
| 发版后的「## 通知」 | 跟着状态（当前版本的通知一句一条，键是版本与内容） | 冒号前半句 / 后半句；类别公告 | 没有链接时只是告知：右栏正文写后半句，列表里截掉的在右栏看得全；应用内链接是操作按钮，https 链接画成二维码（写法见下） | 只显示通知的那一整页、本版新功能页（启动时与设置里）上的通知卡片（都去掉：只在通知里显示） |

通知只读加密的那份：release `notices` 的附件，只给装了应用的人看，每条注明给哪些版本，改了当场生效（`scripts/release-notice.py … --sealed`）。release 正文里的「## 通知」只给没有这套代码的旧版（1.0.9-alpha04 及以前），新版本不读。

一条的写法（解析在 `TvNoticeMarkup`，一句一行，`scripts/release-notice.py` 写入时检查链接）：

- 「标题：说明」，冒号前 30 字以内才拆；说明里写 `
` 分段；`**文字**` 标粗。
- 链接 `[文字](网址)`：
  - `https://…`：电视上在说明下面画二维码，码下写「文字」；触屏上是一颗在浏览器里打开的按钮；手机控制台上是可点的链接。一条只画第一个。
  - 应用内地址是右栏的一颗操作按钮（最多三颗），按钮上写「文字」：`ani://subjects/条目id` 条目详情；`ani://settings/分类[/行]` 设置的一类（账号写 `account`），落在那一行（锚点，如 `ani://settings/about/chat-groups` 是关于页的交流群）；`ani://whatsnew` 本版新功能。
  - 其他（`http`、写错的）只留文字，不出按钮。自己占一段的链接不再写成文字。

本版新功能页照旧是升级后第一次打开时盖的一整页：做成整页正是因为一句话的提示会被随手点掉，新功能没人看到。

订阅接上以后的（在订阅分支上做，见那边的订阅产品设计 `media/subscription-design.md`）：

| 事 | 类 | 标题 / 摘要 | 去处 |
|---|---|---|---|
| 订阅着的作品出了续集 | 消息 | 「「A」的续集「B」已公布」 | B 的订阅弹窗 |
| 在别的设备上把收藏改成了联动清单里的状态 | 消息 | 「在其他设备上将「X」标为在看」 | X 的订阅弹窗 |
| 订阅要处理（等选版本、版本断更、没找到等） | 跟着状态（一部作品一条） | 「「X」找到了版本，请选择」等 | 订阅详情或版本列表 |
| 自动下载整个暂停 | 跟着状态（整机的事，每个档都列） | 「存储设备未连接，自动下载已暂停」等 | 能解决它的设置页 |

## 9. 接口

数据（app-data）：

```kotlin
// data/models/notice/Notice.kt: 存下来的都是字符串, 不存显示的字
@Serializable
data class Notice(
    val kind: String,                           // 种类 id, 如 "feedback.reply"; 界面认不出的不列
    val key: String,                            // 这件事的键; 同一个键只有一条
    val atMillis: Long,                         // 时间; 同一个键的时间变晚算新的; 不知道时给 Notices.UNKNOWN_TIME
    val args: Map<String, String> = emptyMap(), // 文案与去处要用的参数
)

// domain/notice/Notices.kt: 一个用户档的通知 (存在这个档的设置里), Koin 单例
class Notices {
    suspend fun post(notice: Notice)            // 发一条消息; 同键内容没变不动, 变了替换
    suspend fun retract(key: String)            // 撤回一条消息
    fun addSource(source: Flow<List<Notice>>)   // 接上一个跟着状态的来源 (一个进程一次)
    val all: Flow<List<NoticeEntry>>            // 消息 + 各来源的, 带看没看过、读没读过, 排好先后
    suspend fun markSeen(notices: Collection<Notice>)  // 列出来过
    suspend fun markRead(notices: Collection<Notice>)  // 内容显示出来过 / 做过操作 (也就看过)
}

data class NoticeEntry(val notice: Notice, val pending: Boolean /* 跟着状态的 */, val seen: Boolean, val read: Boolean)
```

界面（ui-tv，`ui/notice`）：

```kotlin
/** 一种通知: 类别、标题与摘要、右栏的说明与操作. 一个种类一个文件, 在 TvNotices 的种类表里登记一行 */
interface TvNoticeKind {
    val id: String
    val category: TvNoticeCategory                      // 列表行左边的图标、右栏的类别签
    fun source(): Flow<List<Notice>>? = null            // 跟着状态的来源; 只发消息的为 null
    suspend fun title(notice: Notice): String?          // 标题 (在电视上算, 控制台也用它); null = 不列
    suspend fun summary(notice: Notice): String? = null // 列表里标题下面那一行; null = 没有
    suspend fun cover(notice: Notice): TvNoticeCover? = null // 说的是哪一部作品: 左边画它的封面, 不画类别图标
    fun textChanges(): Flow<*>? = null                  // 标题、摘要与说明还看的状态, 一变全部重算; 只看通知本身的为 null
    fun destination(notice: Notice): TvNoticeDestination?
    suspend fun detail(notice: Notice): TvNoticeDetail? = null  // 右栏的说明与操作; null = 右栏写摘要, 有去处时一个操作「查看」去那里
    fun consoleHref(notice: Notice): String? = null     // 控制台上的去处, 如 "#settings/feedback"
```

- **接一种新的事**：
  1. 在 ui-tv 写一个 `TvNoticeKind`；
  2. 在 `TvNotices` 的种类表里登记一行；
  3. 消息在事件发生处 `Notices.post`；跟着状态的由种类的 `source()` 给出（来源不知道时间时给 `Notices.UNKNOWN_TIME`）。
- **存储**：消息、看过与读过的记录、不知道时间的那几条第一次出现的时刻，按用户档存在设置里（`SettingsRepository.notices`，换用户是重启进程）。
- **认不出的种类**（降级后读到新版本存的）不列，留到过期清掉。参数都是字符串，以后加取值不影响旧版本读。
- **控制台**：`GET api/notices` 列表（标题、摘要、封面、时间、读没读过、跟不跟状态、控制台去处、有没有电视去处）；`POST api/notices/seen`（`key` 可多个）标读过（网页上整条字都写着）；`POST api/notices/open`（`key`）让电视打开通知弹窗、停在这一条（`TvNotices.open`，在别的签里看的开到那个签），先把 Izuko 叫回前台。实时提示搭在网页每 2 秒一次的 `api/notice` 上：回包的 `notices` 里有新的几条（标题与摘要）与条数。
- **调试**（debug 包）：`GET api/debug/notices` 看列表（类别、标题、摘要、封面、看没看过与读没读过、右栏正文与操作、横幅上短按做的那个）与弹窗开没开；`POST api/debug/notices/post`（`kind`、`key`、`arg.<名>`）发一条消息；`POST api/debug/notices/release`（`title` 可多个）换掉当前版本的「## 通知」；`POST api/debug/notices/clear` 撤回全部消息；`POST api/debug/notices/open` 打开通知弹窗；`POST api/debug/notices/foreground` 当作刚从后台回到前台。

## 10. 取舍

**弹窗，不做单独一页。** 电视上手动进一页要先进侧边栏再找；通知又多半是进应用时看一眼。弹窗不占导航，去处是弹窗的直接叠在上面，处理完回到列表。

**入口是侧边栏单独一项「通知」，不放在头像上。** 头像旁写的是「我是谁」（昵称 / 登录），点头像进账号页；通知挂在头像上的话，头像旁那行字要么说身份、要么说点了做什么，两样总有一样对不上。单独一项时红点挂在「通知」上，点它就是通知中心，红点指的与点开的是同一样东西；常驻一项，位置不随有没有通知变，三个页的侧边栏一样。设置里不另放入口：两处都能打开时用户分不清该去哪。

**只在有新的时弹，不是有就弹。** 看过而故意不处理的事（如有意拔掉外接盘）每次都弹，就是每次进应用都要先关一个窗。横幅收起后同一批也不再弹，来了新的才弹。

**进应用时的弹窗一个关了下一个出，通知用横幅。** 控制台二维码是连手机的入口，每次进应用都该看得到，通知弹窗里不再另放一个码；通知与新版本都不急，用右上角的横幅提一句，用户想看再按确定，不用连着关几个窗。新版本做成一条通知，不再单独出一张提示卡：它和别的通知一样在列表里留着、手机上看得到，只剩右上角一条横幅。本版新功能页只在更新后第一次打开时出，排在最前，关掉后照常出二维码与气泡。

**手机上实时提示，不加「连着手机时电视不弹」的开关。** 电视只在有侧边栏的页面弹横幅，播放时不打断；手机上看过的电视就不再弹。两条规则合起来已经是「连着手机就在手机上处理」，不需要再有一个开关。

**不复用上游的站内通知。** 上游的通知由 Ani 服务器下发（评论回复、举报结果、账号安全、公告），去处只有剧集、条目、人物、评论与网页，也没有电视界面；本项目不用 Ani 服务器，这套已经删了。借了它的两点：认识的种类用自己的文案、会加取值的字段存字符串。

**安卓上通知弹窗的内容是原生 View，Compose 画法留给 iPad。** 同设置页：Shield 上量过，Compose 版在列表里上下走一下要重组整个右栏，换签时两栏整个重组，打开时第一帧要组合全部的行（列表上下走 26 帧里 8 帧在主线程超时、换签 99% 81ms、打开 99% 150ms）；原生视图里换一行只换右栏的字，换签只换哪一个列表显示。右栏正文因此是数据（`TvNoticeBlock`），不是一段 Compose：两份画法照同一份数据画，规则（焦点怎么走、提示写什么）两边一样。
