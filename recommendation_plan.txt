用户兴趣不要按“出现次数”简单统计
可以为每部历史作品赋予不同权重：
- 高评分并看完：强正反馈
- 看完但未评分：中等正反馈
- 正在追且进度较高：近期强兴趣
- 想看：弱正反馈
- 搁置：弱负反馈或忽略
- 抛弃、低评分：负反馈
- 越近期的行为权重越高
然后累计到标签上。标签本身也需要降噪：
- “动画”“日本”之类过于宽泛的标签降低权重。
- 在很多作品中都出现的标签降低区分度。
- 在某个条目上只有极少数用户添加的标签降低可信度。
- 同义标签尽可能归并。
最终只选用户最有代表性的约3–6个兴趣方向，而不是遍历全部标签。
不要每个标签独立抽10个
先从各标签产生候选，再合并到一个候选池。作品同时命中多个高权重兴趣时，相关性应该提高，而不是重复出现。
第一版可以采用这样的候选组成，比例只是建议起点：
- 45%：用户高权重标签匹配
- 25%：与近期喜欢作品相似／“看过这部的人也喜欢”
- 15%：当季和近期热度内容
- 15%：相邻兴趣或探索内容
Bangumi 的私有接口文档中还列出了条目推荐关系；如果将来能稳定取得，适合补充“因为你看过《某作品》”这一类召回。Bangumi Private API
把纯随机改成“加权随机”
不要让前500名获得相同概率。可以先为作品计算综合分数：
- 用户标签匹配程度：约45%
- 与喜欢作品的相似度：约20%
- Bangumi 排名、评分与评分人数：约15%
- 新鲜度／当季热度：约10%
- 探索价值：约10%
再根据分数进行加权抽样。高相关作品更容易出现，但中后部作品仍有机会。
为了避免页面一直变化，可以使用“稳定随机”：
- 同一个用户在同一天看到的结果基本稳定。
- 第二天自动换一部分。
- 用户点击“换一批”时才立即更换。
- 已曝光多次但一直未点击的作品逐渐降权。
最后再做一次多样性调整
推荐结果生成后，增加一些简单约束：
- 同一系列或不同季度最多出现一部。
- 同一主标签连续不超过2部。
- 同一年代、制作公司、题材不要占满整行。
- 已看、抛弃和明确不感兴趣的作品排除。
- “想看”作品不要伪装成新推荐，可以放进独立区域。
首页建议怎么分组
第一版不需要很多行，4–6行已经足够：
1. 继续观看
   这是任务入口，不算推荐。
2. 因为你喜欢《最近高评价作品》
   条目相似和标签共同生成，推荐理由最容易理解。
3. 符合你口味的高分动画
   综合多个高权重标签，而不是每个标签单独一行。
4. 本季你可能会喜欢
   避免排行榜让首页永远都是老作品。
5. 换换口味
   与已有兴趣有一两个连接点，但不完全相同。
6. 大家最近在看
   用于冷启动和兴趣信号不足的用户。
不要把“校园”“恋爱”“日常”分别做成三个高度重复的推荐行。只有当某个标签非常强、候选内容足够丰富时，才生成独立行，例如“你喜欢的治愈系动画”。
最终建议
最适合 Animeko 第一版的方向不是一开始做复杂机器学习，而是：
加权兴趣标签 + 多来源候选 + 综合排序 + 受控随机 + 多样性约束 + 推荐理由分行展示。
你的“前500随机10个”可以保留，但建议把它缩小为探索机制：主要结果从个性化排序中产生，约10%–20%的位置再从较大的高质量候选池中随机选择。这样既容易实现，也不会让推荐看起来像换了名称的 Bangumi 标签排行榜。

现在已经有继续播放的分组了，参考上面的做一个方案，把推荐拆成几组。这些算好之后缓存一次，过一段固定时间（或者收藏状态更新作为条件等）才重新算（而且最好是空闲时间）
